# Figures and tables

This is a companion to the writing workflow, not a requirement to redesign figures during every prose edit. Use suitable drawing or presentation tools available in the current environment. Do not require a particular external image service merely to use this skill.

## Define the figure's job

Distinguish three kinds of figure:

1. **Conceptual framework:** constructs, theoretical relationships, and the perspectives integrated.
2. **Analytical workflow:** data, transformations, methods, and outputs.
3. **Empirical result:** values, uncertainty, contrasts, and patterns supported by data.

Do not label a calculation pipeline a purely conceptual framework. If operational indicators are included intentionally, make their status clear and align the title and caption with what is actually shown. Do not use arrows that imply a tested causal mechanism when they only indicate data flow or conceptual association.

## Concept and workflow diagrams

- Keep the title short and descriptive; the caption can supply scope. Avoid calling a figure “a novel comprehensive framework” instead of naming the relationship.
- Distinguish constructs from their indicators and from their data sources.
- Use consistent reading direction, alignment, box hierarchy, arrow meaning, typography, and construct labels.
- Color should help track the same concept across panels or figures, not create a new category without explanation.
- Include only the labels needed to understand the argument. Move extraction prompts, API settings, and detailed scoring rules to the methods figure or supporting material.
- Check spelling, arrow endpoints, line crossings, spacing, text fitting, panel letters, and legibility at the actual manuscript size.

If an editable PowerPoint framework is requested, retain a real editable PPTX rather than a screenshot inserted into a slide and described as editable. Store the current framework sources together in a clearly named `ppt-framework` package when that organization is requested. Do not overwrite the only editable source with a flattened export.

## Data figures and version control

Use the actual analysis outputs. Do not generate a visual resemblance to a heatmap by guessing its matrix. Keep the data, script or notebook, configuration, sample definition, and final figure traceable to one another.

When asked to update values without changing the visualization, retain the original plotting code and layout wherever possible. Change the verified inputs and check that titles, annotations, intervals, sample sizes, and captions update consistently. If the existing layout clips new labels or ranges, make the smallest necessary repair and explain it.

Keep consistent units, color direction, scale interpretation, uncertainty notation, group order, and reference categories. Explain differences between years or panels rather than silently changing the scale. An alternative model or repeated-run figure should identify what was compared and what the reported statistic establishes.

Use a scientific plotting workflow for precise charts. An image generator may help with an illustrative diagram when authorized, but not with fabricating data, exact numerical labels, or analytical outputs.

## Captions and manuscript links

Give the figure a compact identity and enough explanation to read it correctly. Put common methodological details in the relevant Methods or Results paragraph when a caption becomes disproportionately long. Keep indispensable panel definitions, units, uncertainty, and symbol explanations accessible; a shorter caption must not become uninterpretable.

Avoid duplicating a long title inside both the figure and caption. Keep labels consistent with the manuscript's terminology, including whether quality is area-level, whether prices are recorded categories, and whether an outcome is observed or simulated.

After moving caption material into the text, check the response letter and any references to its location. Never shorten by deleting qualifiers that change the result.

## Tables

Use compact phrases in cells, keeping full argumentation in the surrounding prose. Retain units, definitions, reference categories, uncertainty, sample sizes, and notes needed to interpret the entries. Do not abbreviate a construct differently in each table.

Use consistent font, size, alignment, decimal precision, symbols, and notes for the same table roles. Brad's default Word table text is 10.5 pt when readable and compatible with journal requirements. Do not force every table to that size if it makes the result unreadable.

Check repeated headers, row splits, single-row page fragments, and captions separated from their tables. When needed, move a table or a short surrounding paragraph to improve pagination before reducing type size.

## Visual acceptance and source preservation

Inspect the rendered figure and the figure as placed in the manuscript; a good standalone image can become unreadable after resizing. Check relevant pages after replacing any figure or changing a caption.

Retain current figure exports, editable sources, and the code/data needed for the requested reproducibility scope. Do not create a stack of historical ZIPs automatically or delete older assets without explicit authorization. Publish only the material approved for public sharing, with no embedded credentials, confidential data, reviewer identities, or unpublished manuscript content.
